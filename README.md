# Хакатон "Помоги даркстору" от ВкусВилл. Трек 3. Параллельная сборка заказов

## Проблематика и что необходимо реализовать

При большом объеме заказов ВкусВилл запускает параллельную сборку. В таком случае сборщик может собирать до трех заказов одновременно и чаще допускает ошибки.
Необходимо изучить процесс, найти варианты его оптимизации и/или проанализировать существующие решения на рынке. Ключевые проблемы при сборке: процент ошибки в заказах, среднее время сборки заказа.

## Описание

В рамках хакатона было предоставлено продуктовое решение кейса, идеи по оптимизации и переработка UI-интерфейса для оборудования, использующегося при сборке заказа.
Программное решение - это оптимизированный аналитический ETL-процесс, представляющий из себя сегментатор для оптимизированного разбиения заказов для их параллельной сборки.
Далее опишу именно программную часть, которую решает разработанный сегментатор. 

## Запуск

Для запуска использовались развернутые ресурсы, которые были предоставленны организаторами хакатона. Былы выделена нода c вычислительными ресурсами и развернутый в k8s hdfs.
С нашей стороны был установлен Spark и подтянуты python зависимости ддля работы с pyspark из файла requirements.txt

## Функционал проекта

Необходимо ускорить процесс сборки заказа работником ДС. Для этого оптимизируем пуллинг заказов. Будем матчить заказы не по равному кол-ву товаров, а используем ограничение по суммарному кол-ву товаров в СЛ. Также обращаем внимание на кол-во категорий товаров в заказах. Товары схожих категорий лежат рядом -> сборщик проходит меньше кол-во точек при сборке СЛ.

## Условия сегментации для возможности спулливания заказов 

- Суммарное кол-во строк в СЛ не превышает заданное на ДС
- Заказы поступили примерно в одно время (разница между заказами не более 40 минут)
- Особо крупные товары не попадают в спуленные СЛ
- Экспресс-заказы не попадают с спуленные СЛ
- Производится подбор по схожести категорий товаров, наполняющих каждый из потенциально-спуленных заказов
- Остальные заказы возвращаются к работе для обработки стандартным алгоритмом спулливания, работающим на данный момент
